# T3h2 — skeleton streaming

- 2026-08-31 18:10 UTC — Vervolgtrack gestart vanaf verse `origin/main` op merge `c86a5a3`; branch `track/t3h2-skeleton-streaming`. PO-observatie en diagnose bevestigd als doel: een L1/L2-batch mag het histogram niet pas na een chunk- of await-allbarrière publiceren. Plan: bestaande requestcoalescing behouden, frames binnen bereikresponses incrementeel decoderen/publiceren, UI-updates per animation frame bundelen, een test toevoegen die meer dan N tussenstappen afdwingt, en alle gates inclusief twee opeenvolgende e2e-runs uitvoeren.
- 2026-08-31 18:26 UTC — Streamingkern en warme locatiewissel geïmplementeerd. Een gecoalesceerde Range-response vult nu een oplopende payloadspan; elk onafhankelijk zstd-frame wacht alleen op zijn eigen eindoffset, decodeert direct in de worker en meldt puntserievoortgang zonder chunk-/`Promise.all`-barrière. Histogrampublicaties worden per rAF gebundeld. Een nieuwe locatie bemonstert alle aanwezige decoded frames meteen; bij een volledig warme reeks blijft `data-load-stage=complete`, verandert geen enkele balk in skeleton en start geen scheduler/fetch. De decoded LRU is 512 frames zodat de volledige huidige synth/live-veldset tegelijk beschikbaar blijft. Unitreceipts: typecheck exit 0; Vitest 79/79, inclusief 25 nowcastframes in >5 voortgangsstappen tijdens één lopende Range. Eerste echte Caddy-run bracht twee integratiefouten aan het licht en die zijn hersteld: native rAF moet via een window-gebonden wrapper worden aangeroepen; een voltooide reader mag niet worden gecanceld omdat Chromium dat als `net::ERR_ABORTED` rapporteert. Gerichte desktop-e2e daarna green: passief 547.578 B, L2 174,2 ms / 4 transfers voor 85 frames, warm 0 B, synchrone locatiewissel zonder skeletonmutatie en tweede klik 0 requests.
