# mrf v0 core

`mrf` is an intra-only container: each payload frame is a standalone zstd member, so a consumer can fetch and decode any frame using the payload-relative `offset` and `len` in the JSON header. `header_len` for the manifest is always `8 + JSON-header-byte-length`.

## Quantization v0

The built-in table below is the rain-rate table. The encoder writes the
complete table in every header; signed fields may use a different strictly
increasing table with a negative index 0. Only index 255 being null is
universal; `rain_rate` and `radiation` additionally require index 0 to be
zero. The extra field tables are specified in `docs/fields.md`.

The rain table has 256 entries:

- `table[0] = 0.0` mm/h.
- For `i = 1..=254`, `table[i] = 0.01 * (150.0 / 0.01)^((i - 1) / 253)` mm/h.
- `table[255] = null`, the no-data mask.

`quantize(f32)` applies that table as follows: NaN becomes 255; values below half of `table[1]` become 0; values at or above `table[254]` become 254; all other values use the nearest table entry. Exact midpoints choose the lower index. Consumers must read the header's table, rather than assume this curve.

## Compression level

The core uses zstd level 19. On twelve deterministic sparse, smooth 700×765 synthetic fields used by the test suite (about 8% coverage), level 3 produced 15,260 bytes and level 19 produced 10,692 bytes. The write-once/read-many byte saving justifies its ingestion-only CPU cost. Reproduce with `devenv shell cargo test --test mrf level_19_beats_level_3_on_sparse_advecting_fields -- --nocapture`.

## CLI raw input

`mrf encode --input field.f32le --meta meta.json --output chunk.mrf` reads a concatenation of row-major frames, each `width × height` IEEE-754 `f32` values in little-endian byte order. `meta.json` is:

```json
{
  "grid": { "crs": "EPSG:3857", "x0": 0.0, "y0": 0.0, "dx": 1000.0, "dy": -1000.0, "width": 2, "height": 2 },
  "quant": [0.0],
  "source": "synthetic",
  "run": "2026-08-28T12:00:00Z",
  "times": ["2026-08-28T12:00:00Z"]
}
```

The example abbreviates `quant`; real input must contain the valid 256-entry table from the desired mrf header (the built-in v0 table is generated by the library). `mrf inspect chunk.mrf` prints the header and frame table. `mrf decode chunk.mrf 0 --output frame.u8` writes the selected quantized row-major frame as raw bytes.
